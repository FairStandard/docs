FairStandard's relations service: the workspace-scoped graph of what
relates to what — typed edges, bulk onboarding loads, and facts projected
from the platform's shared stream (ADR 0001). See `CONTEXT.md` for the
domain glossary and `docs/adr/` for the decisions this service is built
on.

## Package layout

This is a proper installable package (`src/relations_api/`, `uv_build`
backend), not just an HTTP service — the vocabulary and the wire codec
(`Fact`, `Reference`, `FactCodec`, `RELATION_KINDS`, `REFERENCE_TYPES`,
`validate_kind`, `validate_reference_type`) are meant to be imported
in-process by other repos that pin this package the same way they pin
`servicekit` (`[tool.uv.sources]`). See `src/relations_api/__init__.py`
for what's exported. `relations_api.main` (the FastAPI app) and
`relations_api.store` are deliberately not part of that surface —
nothing needs to build an HTTP app or open a database engine just to
validate a relation kind.

## Architecture

- **Vocabulary** (`src/relations_api/vocabulary.py`) — the relation
  kinds and reference types are `Literal` types; `RELATION_KINDS` and
  `REFERENCE_TYPES` are derived from them with `typing.get_args`, so
  the tuple can never drift out of sync with the type.
- **Store** (`src/relations_api/store.py`) — the `edge` table: idempotent
  single-fact writes, a raw-driver `COPY`-backed bulk door for onboarding
  bursts, and workspace-scoped neighborhood/two-hop reads. This service
  never calls another service (ADR 0003) — everything arrives.
- **Models** (`src/relations_api/models.py`) — the `edge` table is
  hash-partitioned by `workspace_id` (ADR 0002); `partition_ddl()` is the
  single source of truth for the partitions, used by both the alembic
  migration and the test fixtures.
- **Projector** (`src/relations_api/projector.py`) — consumes the
  service's private fact stream and writes edges, forever. Runs beside
  the HTTP surface as its own process: `uv run python -m
  relations_api.projector`.
- **Queueing** (`src/relations_api/queueing.py`) — the `Fact` wire codec
  (validates on decode, so a poison fact dead-letters from the decode
  itself) on top of `servicekit`'s `StreamQueue`.

## HTTP surface

Internal only, workspace-scoped by `X-Workspace-Id`:

- `POST /internal/bulk` — onboarding door: a burst of facts in,
  `{received, written}` out.
- `GET /internal/neighborhood/{reference_type}/{reference_id}` — every
  edge touching one reference, in one workspace.
- `GET /internal/two-hop/{reference_type}/{reference_id}` — the
  neighborhood plus everything touching it.
- `GET /health`

`reference_type`, `subject_type`/`object_type`, and `kind` are typed as
the vocabulary's `Literal`s directly on the request models, so FastAPI
rejects an unknown value with `422` before any handler code runs.

## Database migrations

Alembic (async, `asyncpg`), configured against `RELATIONS_DATABASE_URL`
(matching `settings.py`'s `RELATIONS_` prefix — never a bare
`DATABASE_URL`):

```
uv run alembic upgrade head
uv run alembic revision --autogenerate -m "..."
```

The base tables are autogenerated from `models.SQLModel.metadata`; the
hash partitions behind them are wired into each migration's marked
customization area via `models.partition_ddl()`, not hand-copied DDL.

## Setup

```
uv sync --dev
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run pyrefly check
```

`uv sync` needs read access to the private `servicekit` repository (see
`pyproject.toml`'s `[tool.uv.sources]` for the pinned revision); CI
authenticates via the `SERVICEKIT_TOKEN` secret. Tests spin up
disposable Postgres (`apache/age:latest`, for `AGE`-compatible
partitioning) and Redis containers via `testcontainers` — Docker must be
available.
